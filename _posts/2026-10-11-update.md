## Featured PRs

### [142913: [KEP-4443] Add more granular job failure condition reasons](https://github.com/kubernetes/kubernetes/pull/142913)

[ameukam](https://github.com/ameukam) added more granular failure condition reasons for Jobs using `PodFailurePolicy`. Previously, multiple rules using the `FailJob` action could produce the same generic failure reason, making it difficult for higher-level controllers to determine why a Job failed. This change allows rules to be named so that the resulting Job failure condition can identify the rule responsible, falling back to the rule's index when no name is specified. This gives controllers such as JobSet more precise information to make decisions about retries and recovery. The change is part of [KEP-4443](https://github.com/kubernetes/enhancements/tree/master/keps/sig-apps/4443-configurable-pod-failure-policy-reasons).

### [142898: e2e: test KEP-4006 WebSocket exec, attach and port-forward without SPDY fallback](https://github.com/kubernetes/kubernetes/pull/142898)

[seans3](https://github.com/seans3) added end-to-end tests for `exec`, `attach`, and `port-forward` over WebSockets without allowing a fallback to SPDY. Tests that permit fallback can pass even when the WebSocket path is broken, leaving gaps in coverage for Kubernetes' transition away from SPDY. By explicitly exercising these operations without fallback, this change helps verify that WebSocket streaming works independently and provides stronger confidence in the new protocol paths. The work is part of [KEP-4006](https://github.com/kubernetes/enhancements/tree/master/keps/sig-api-machinery/4006-transition-spdy-to-websockets), with promotion of the tests to conformance planned as a follow-up after a soak period.

### [142897: apiserver, kubelet: graduate the KEP-4006 WebSocket streaming metrics to BETA](https://github.com/kubernetes/kubernetes/pull/142897)

[seans3](https://github.com/seans3) graduated WebSocket streaming metrics in the API server and kubelet from Alpha to Beta as part of [KEP-4006](https://github.com/kubernetes/enhancements/tree/master/keps/sig-api-machinery/4006-transition-spdy-to-websockets). The metrics provide visibility into WebSocket streaming requests handled by the API server and kubelet, including requests processed through the API server's stream translator and tunnel. Advancing these metrics to Beta improves their stability and makes them more useful for monitoring and troubleshooting as Kubernetes continues its transition from SPDY to WebSockets.
