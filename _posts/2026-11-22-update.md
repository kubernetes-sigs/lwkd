## Developer News

The Release Team has [announced changes to the Release Exception Request process](https://groups.google.com/a/kubernetes.io/g/dev/c/JdfTUW6R5jk) in response to a rapid increase in KEP exception requests; KEP authors and SIG leads should review the updated expectations before submitting new requests.

[WG governance has been clarified around approval authority and solicited +1s](https://github.com/kubernetes/community/pull/9268): the update tightens how WG proposals are approved and when solicited +1s from reviewers carry weight, affecting all future WG proposals and changes.

[SIG Cluster Lifecycle has updated its charter](https://github.com/kubernetes/community/pull/9173) to reflect the SIG's current scope and governance structure, following the recent chair and tech lead transitions.

SIG Autoscaling has [added Karpenter Working Group meetings to the karpenter subproject](https://github.com/kubernetes/community/pull/9259), formally integrating Karpenter's governance structure under SIG Autoscaling.

The [Security Response Committee membership has been updated](https://github.com/kubernetes/community/pull/9260); SRC coordinates handling of security advisories like the September and October CVEs covered in earlier editions.

## Featured PRs

### [144452: Promote ConcurrentWatchObjectDecode to GA in 1.39](https://github.com/kubernetes/kubernetes/pull/144452)

[Jefftree](https://github.com/Jefftree) graduated `ConcurrentWatchObjectDecode` to General Availability in Kubernetes 1.39 and locks the feature gate to its default state. Concurrent watch object decoding allows the API server to decode watch objects concurrently, improving the efficiency of processing watch events. Graduating the feature to GA makes this capability generally available without requiring users to enable the feature gate. This work is tracked in [KEP-6178](https://www.kubernetes.dev/resources/keps/6178/).

### [144475: dynamicresources: release pending allocation when the claim is stored](https://github.com/kubernetes/kubernetes/pull/144475)

[logica0419](https://github.com/logica0419) fixed a Dynamic Resource Allocation (DRA) scheduling regression where pending allocations could remain in-flight while a Pod waited for binding conditions. If that Pod was deleted, other Pods waiting for the same devices could be rejected because the allocation was still considered in-flight, leaving them in the unschedulable queue until the periodic flush. This change releases the pending allocation immediately after the ResourceClaim is stored, while retaining the allocation on failure so other Pods in the same PodGroup can still use it. It also ensures each Pod releases only the allocation share it acquired. The change addresses [#144110](https://github.com/kubernetes/kubernetes/issues/144110).

## KEP of the Week

### [KEP-6404: API Server Write Throughput: Reducing Allocations](https://github.com/kubernetes/enhancements/blob/master/keps/sig-api-machinery/6404-apiserver-write-throughput/README.md)

A burst of conflicting writes can slow the Kubernetes API server even after
traffic eases. Each retry can mean another read from etcd and another decode of
the entire object. KEP-6404 routes consistent single-object reads and reads for
write retries through the watch cache. The API server waits for the cache to
catch up, then reuses objects it has already decoded. That wait can make
individual reads slower, but it reduces work for etcd when writes pile up.

[serathius](https://github.com/serathius), [jpbetz](https://github.com/jpbetz),
and [Jefftree](https://github.com/Jefftree) developed the KEP in SIG API Machinery
with SIG Scalability after a [September throughput investigation](https://github.com/kubernetes/kubernetes/issues/142223).
The [implementation PR](https://github.com/kubernetes/kubernetes/pull/143833)
enabled `ConsistentGetFromCache` by default and reported higher sustained Pod
patch throughput in its benchmark. The [November 16 KEP update](https://github.com/kubernetes/enhancements/pull/6516)
recorded the promotion to Beta in v1.38. The KEP is `implementable`, and the
[enhancement issue](https://github.com/kubernetes/enhancements/issues/6404)
tracks the work.


## Other Merges

* Added an alpha [spec.podNetwork field to Pods](https://github.com/kubernetes/kubernetes/pull/143280) (NetworkIsolatedPods feature gate) with values Default and Isolated; Isolated runs the pod in a network namespace with only a loopback interface, not attached to the pod network, and such pods get no pod IP
* Add [per-pod PID limits](https://github.com/kubernetes/kubernetes/pull/139277) (alpha, PerPodPIDLimit feature gate): spec.resources.limits.pids limits the total number of processes in a pod, and the effective limit is min(node podPidsLimit, pod pids limit)
* Added the alpha [WorkloadControlledSwap feature](https://github.com/kubernetes/kubernetes/pull/142885): pods can declare resources.limits.swap at container and pod level, and swap limits can be changed in place through the pod resize subresource
* Added the alpha [DRAPreemption feature gate](https://github.com/kubernetes/kubernetes/pull/143456) for kube-scheduler; when enabled, the scheduler can preempt lower-priority pods that use exclusively allocated node-local devices in pod-owned ResourceClaims, and holds the freed devices for the preemptor until it gets scheduled
* Added alpha support for [dynamically adding and removing node-local ephemeral volumes](https://github.com/kubernetes/kubernetes/pull/143709) (emptyDir, configMap, secret, projected, image) under the /dynamic subresource, behind the DynamicNodeLocalEphemeralVolumes feature gate
* Kubelet now [honors a shorter grace period](https://github.com/kubernetes/kubernetes/pull/113883) specified in a subsequent Pod deletion request
* Added alpha support for [workload-aware scheduling in Deployments](https://github.com/kubernetes/kubernetes/pull/143235) through .spec.scheduling; requires the WorkloadWithDeployment feature gate, which is disabled by default
* kube-apiserver has a new alpha flag, [--storage-compression-config](https://github.com/kubernetes/kubernetes/pull/144186), that points at a StorageCompressionConfiguration file selecting resources to compress before they're stored in etcd
