## Featured PRs

### [144232: kubelet: add pod-level resize metrics for KEP-5419](https://github.com/kubernetes/kubernetes/pull/144232)

[ndixita](https://github.com/ndixita) added kubelet metrics for tracking in-place Pod-level resource resizes as part of [KEP-5419](https://www.kubernetes.dev/resources/keps/5419/). The change introduces the alpha `kubelet_pod_requested_resizes_total` metric and extends existing resize metrics with `container_resources` and `pod_resources` labels to distinguish container-level and Pod-level resize operations. These metrics provide better visibility into resize requests, pending and in-progress operations, infeasible resizes, and deferred resizes. This improves observability for workloads that use Pod-level resource requests and limits without requiring Pod recreation.

### [144299: scheduler_perf: add DRA scoring benchmark with partitionable devices](https://github.com/kubernetes/kubernetes/pull/144299)

[zl86790](https://github.com/zl86790) added a `PartitionableDeviceScoring` benchmark to the scheduler performance suite to cover DRA-backed extended-resource scoring with partitionable devices. The benchmark combines partitionable devices, shared counter sets, and extended-resource scoring to exercise the device-class matching cache path across scheduling cycles. It includes a fast integration-test workload with 4 nodes and 4 Pods, as well as a larger performance workload with 1,000 nodes and 2,000 Pods. This fills a benchmark coverage gap identified while investigating [PR #144108](https://github.com/kubernetes/kubernetes/pull/144108), helping evaluate scheduler scoring performance for partitionable-device workloads.

## KEP of the Week

### [KEP-6386: Ephemeral Storage Support for Pod-Level Resource Specifications](https://github.com/kubernetes/enhancements/blob/master/keps/sig-node/6386-pod-level-ephemeral-storage/README.md)

Pods can share disk-backed `emptyDir` volumes, but today ephemeral-storage
requests and limits are set per container. That makes it hard to budget shared
storage and can let an injected sidecar's limit unintentionally cap the whole
Pod. KEP-6386 proposes Pod-level ephemeral-storage requests and limits behind
the `PodLevelResourcesEphemeralStorage` feature gate. The design updates the
scheduler, quota and LimitRanger handling, and kubelet eviction manager;
the existing accounting of writable layers, container logs, and disk-backed
`emptyDir` volumes stays the same. In-place resizing is out of scope.

[ndixita](https://github.com/ndixita) authored the KEP for SIG Node, with SIG
Storage participating. The proposal builds on [KEP-2837](https://github.com/kubernetes/enhancements/blob/master/keps/sig-node/2837-pod-level-resource-spec/README.md),
which introduced Pod-level CPU and memory resources and deferred ephemeral
storage. The [Kubernetes implementation PR](https://github.com/kubernetes/kubernetes/pull/143777)
is open. KEP-6386 is `implementable`, targets Alpha in v1.38, Beta in v1.39,
and Stable in v1.41; its [enhancement issue](https://github.com/kubernetes/enhancements/issues/6386)
tracks the work.


## Other Merges

* Alpha support for [container cgroup mounts through securityContext.cgroupOptions.mountMode](https://github.com/kubernetes/kubernetes/pull/137568), including rw cgroup v2 access for unprivileged containers, behind the CgroupOptions feature gate (disabled by default)
* A new [pods/dynamic subresource](https://github.com/kubernetes/kubernetes/pull/143715) allows regular containers to be added to and removed from running pods, behind the DynamicContainers alpha feature gate
* Alpha [LeaderElectionRecovery feature gate](https://github.com/kubernetes/kubernetes/pull/143717): kube-controller-manager keeps running after failing to renew its lease, rejects controller writes while not the leader, and resumes once it renews it; the [namespace controller pauses and resumes the same way](https://github.com/kubernetes/kubernetes/pull/143766)
* [EnvFiles GA graduation reverted](https://github.com/kubernetes/kubernetes/pull/143983); EnvFiles remains Beta, enabled by default
* Kubelet [pulls OCI seccomp profiles through the container runtime](https://github.com/kubernetes/kubernetes/pull/142515) before starting a pod, behind the alpha SecurityProfileOCI feature gate
* Alpha [DRAExtendedResourceCapacity feature gate](https://github.com/kubernetes/kubernetes/pull/143779): a DeviceClass can set spec.extendedResourceCapacityRequests so extended resource requests consume capacity from shareable DRA devices
* DeviceTaintRule.spec.deviceSelector gains a [boolean all field](https://github.com/kubernetes/kubernetes/pull/142287) that matches every device from every driver; it can't be set to false
* kube-apiserver gets a [--disable-pod-subresources flag](https://github.com/kubernetes/kubernetes/pull/143364) to disable select pod subresources
* kubectl drain and uncordon [write DrainInProgress and Drained Node conditions](https://github.com/kubernetes/kubernetes/pull/143313)
* New [numa-allocation-strategy Topology Manager option](https://github.com/kubernetes/kubernetes/pull/142226) breaks ties between equally good NUMA affinities by how much of each NUMA node is allocated; requires the TopologyManagerPolicyAlphaOptions feature gate
