## Featured PRs

### [141959: Conditional Authz [4/n]: Add conditional authz support to kube-apiserver](https://github.com/kubernetes/kubernetes/pull/141959)

[luxas](https://github.com/luxas) advanced [KEP-5681: Conditional Authorization](https://github.com/kubernetes/enhancements/issues/5681) by adding conditional authorization support to the kube-apiserver. Conditional authorization lets an authorizer return requirements that depend on request-object content, which the API server can evaluate later during admission instead of making a decision solely from request metadata. This PR is the fourth part of the implementation series and builds on earlier core machinery, enabling more context-aware authorization policies for Kubernetes APIs.

### [141878: scheduler, api: implement alpha allowDisruptionByPriorityGreaterThanOrEqual (KEP-3280)](https://github.com/kubernetes/kubernetes/pull/141878)

[NAVEENKUMARRK777](https://github.com/NAVEENKUMARRK777) implemented the alpha `allowDisruptionByPriorityGreaterThanOrEqual` capability described in [KEP-3280](https://github.com/kubernetes/enhancements/tree/master/keps/sig-scheduling/3280-pod-disruption-conditions). The change adds API and scheduler support for controlling which lower-priority workloads may be disrupted, based on a priority threshold. This gives workload authors and cluster operators more precise control over disruption behavior for priority-sensitive applications.

### [141860: Implement recursive statuses for Composite Pod Groups](https://github.com/kubernetes/kubernetes/pull/141860)

[jdizkowski](https://github.com/jdizkowski) implemented recursive status handling for CompositePodGroups, part of the [CompositePodGroup API proposal (KEP-6012)](https://github.com/kubernetes/enhancements/tree/master/keps/sig-scheduling/6012-composite-pod-groups). CompositePodGroups are intended to represent hierarchical, heterogeneous workloads whose components may have different scheduling requirements. This PR propagates status through the hierarchy, allowing users and controllers to observe the aggregate state of complex workload groups instead of inspecting each child PodGroup separately.

## KEP of the Week

### [KEP-6058: CSI global mount fallback for volume reconstruction](https://github.com/kubernetes/enhancements/pull/6059)

This enhancement extends [KEP-3756](https://github.com/kubernetes/enhancements/tree/master/keps/sig-storage/3756-volume-reconstruction) to recover CSI volumes after a kubelet restart when pod-local `vol_data.json` metadata is missing or corrupt. Without the fallback, a global mount can remain active after its Pod directory disappears, causing the volume to leave `node.status.volumesInUse` and potentially allowing a ReadWriteOnce filesystem to be attached to another node. The proposal lets kubelet reconstruct the volume from metadata stored beside the global mount, then verify or unstage it through the normal volume-manager flow.

The work builds on a long-standing reconstruction problem tracked in [kubernetes/kubernetes#101791](https://github.com/kubernetes/kubernetes/issues/101791) and the manual-cleanup procedure documented by KEP-3756. [cniackz](https://github.com/cniackz), with SIG Storage and SIG Node contributors including [jsafrane](https://github.com/jsafrane) and [gnufied](https://github.com/gnufied), is implementing the fallback in [kubernetes/kubernetes#138454](https://github.com/kubernetes/kubernetes/pull/138454). The KEP is implementable, and its KEP and implementation updates are currently under review.

KEP 6058 is targeting Alpha in Kubernetes v1.38.

The change is opt-in behind a new alpha feature gate and affects kubelet CSI reconstruction and unmounting. It is intended to prevent leaked global mounts and reduce the risk of double-mounting and data corruption on storage systems such as Fibre Channel, iSCSI, and EBS.

## Other Merges

* Fixes an [apiserver watch cache metric bug](https://github.com/kubernetes/kubernetes/pull/141333) where `events_dispatched_total` was incremented for undispatched bookmarks.
* [Renames `endpoint_slice_controller_changes` to `endpoint_slice_controller_changes_total`](https://github.com/kubernetes/kubernetes/pull/140447) to add the conventional `_total` suffix; the old name is retained temporarily for backward compatibility.
* Clarifies that the [`/flagz` endpoint reflects flag layer, not effective config](https://github.com/kubernetes/kubernetes/pull/140233).
* apiserver: clients now [receive a resource version when deleting objects](https://github.com/kubernetes/kubernetes/pull/138724).
* client-go: a non-nil `NegotiatedSerializer` in `rest.Config` is [now used when constructing clientsets](https://github.com/kubernetes/kubernetes/pull/140317) instead of being overwritten.
* `resource.Quantity` fixes: [`Neg()` and `Sub()` no longer overflow on `math.MinInt64`](https://github.com/kubernetes/kubernetes/pull/141264), [`String()` no longer drops the magnitude of values above 10^18](https://github.com/kubernetes/kubernetes/pull/140459), and [`Value()`/`MilliValue()` round negative values away from zero](https://github.com/kubernetes/kubernetes/pull/138510).
* The OpenAPI schema for admission policy bindings now [marks `spec.paramRef.parameterNotFoundAction` as required](https://github.com/kubernetes/kubernetes/pull/141527), matching apiserver validation.
* scheduler: PodTopologySpread [no longer ignores constraints with an empty `labelSelector: {}`](https://github.com/kubernetes/kubernetes/pull/141340), and the scheduling queue [stops running PreEnqueue plugins after the first gated pod in a PodGroup](https://github.com/kubernetes/kubernetes/pull/141577).
* Job controller [retries removing the tracking finalizer](https://github.com/kubernetes/kubernetes/pull/141329) so Pod removal is no longer blocked.
* CPU Manager: [fixes a kubelet hang during admission with `distribute-cpus-across-numa` and `full-pcpus-only`](https://github.com/kubernetes/kubernetes/pull/140730), [makes `distribute-cpus-across-cores` use CPU topology](https://github.com/kubernetes/kubernetes/pull/140766), and [fixes drifting allocation metrics](https://github.com/kubernetes/kubernetes/pull/141261).
* DRA: a DeviceTaintRule without `spec.deviceSelector` [now matches no devices instead of every device](https://github.com/kubernetes/kubernetes/pull/141648); use `deviceSelector: {}` to target all devices.
* DRA: [prevents exclusive allocation of a device that still has a live shared allocation](https://github.com/kubernetes/kubernetes/pull/140798), [preserves `TimeAdded` for unchanged device taints](https://github.com/kubernetes/kubernetes/pull/141107), [fixes a panic in drivers calling `UpdateStatus` via the v1beta2 client](https://github.com/kubernetes/kubernetes/pull/141106), and [fixes plugin registration with 108-byte Unix socket paths](https://github.com/kubernetes/kubernetes/pull/141815).
* kubectl top pod: [fixes `--sum` alignment with `--show-swap`](https://github.com/kubernetes/kubernetes/pull/141621) and [documents filtering by node with `--field-selector`](https://github.com/kubernetes/kubernetes/pull/141656).
